# Batch Run 底部面板设计说明

## 目标

把 Batch Run 面板与 Log 面板统一放在画布底部，通过底部状态栏按钮打开，并让 Batch Run 的展开、全屏和列表交互与 Log 面板保持一致。

本文档与当前实现同步；后续行为变化应同步更新本文。

## 底部入口

在底部状态栏现有 `Log` 按钮右侧增加 `Batch` 按钮。

- `Log` 按钮用于打开底部工作区并选中 `Logs` Tab。
- `Batch` 按钮用于打开底部工作区并选中 `Batch Run` Tab。
- 如果底部工作区已经展开，点击对应按钮时只切换 Tab，不重复改变面板高度。
- 底部工作区默认仍可以使用现有的停靠高度。
- 双击面板空白区域时，`Batch Run` 和 `Logs` 一样扩展到整个画布区域；再次双击恢复到底部停靠高度。
- 面板展开、收起、全屏状态由底部工作区统一管理，不分别维护两套高度状态。

## Batch Run 面板布局

Batch Run 面板内部以 workflow 列表为主要内容。

每条 workflow 使用一行显示，按从上到下的顺序排列。每一行至少包含以下内容：

1. workflow 显示名称
2. workflow 文件完整路径
3. 当前实例数量
4. 当前运行状态
5. 与该 workflow 对应的运行实例摘要

如果 workflow 来源是当前编辑器快照，应明确显示为“当前编辑器快照”，不要伪装成普通文件路径。

### 尺寸比例

Batch Run 的行高必须与 Logs 面板中的单条日志行保持一致，不能单独设计更高或更矮的行。

约定如下：

- workflow 单行使用与日志列表项相同的 `MinHeight`、垂直内边距和垂直居中方式。
- `Run`、`Stop`、`Open` 三个按钮所在行的垂直高度、控件间距和上下边距，应与 Logs 面板顶部含按钮的工具栏保持相同的视觉比例。
- 按钮、实例数量选择框等控件应使用相同或相近的控件高度，不得明显高于 Logs 面板中的同类控件。
- 当窗口变宽或变高时，应优先扩展路径和状态区域，而不是同比放大按钮或行高。

### 主题适配

Batch Run 面板必须同时适配明色主题和暗色主题。

- 背景、前景、边框、按钮、悬停、按下、禁用和错误提示颜色必须使用现有主题资源。
- 不得在 Batch Run 控件中写死只适合单一主题的颜色值。
- Batch Tab 与 Logs Tab 在两种主题下的 Tab 背景、选中状态和内容背景应保持一致的视觉层级。
- 路径和次要信息可以使用主题中的次级文字颜色，但仍必须保证两种主题下可读。

## 每行操作按钮

每条 workflow 行的最左侧放置三个按钮，顺序为：

- `Start`：只启动该行对应的 workflow。
- `Stop`：只停止该行对应的 workflow 实例。
- `Open`：打开该行对应的 workflow 文件。

`Open` 按钮右侧显示该行 workflow 文件的绝对路径。路径应完整展示并支持悬浮提示，空间不足时可使用省略显示，但不得只显示文件名。

三个按钮应复用工具栏按钮的外观风格，保持尺寸、圆角、颜色、悬停、按下和禁用效果一致，并同时适配明暗主题。

按钮行为必须严格限定在当前 workflow 行内：

- `Start` 不会启动列表中的其他 workflow。
- `Stop` 不会停止列表中的其他 workflow。
- `Stop` 不应等价于 Batch Run 的 `Stop all`。
- 某一行的操作失败时，不能影响其他行继续运行。

## 行状态显示

每个 workflow 行需要能够显示以下运行信息：

- 已配置的实例数量
- 当前运行中的实例数量
- 已完成实例数量
- 失败实例数量
- 最近一次错误信息
- 当前行是否正在运行

建议 `Run` 和 `Stop` 根据当前行状态控制可用性：

- 行未运行时，`Start` 可用。
- 行运行中时，`Start` 禁用。
- 行运行中或存在可停止实例时，`Stop` 可用。
- 行没有运行实例时，`Stop` 禁用。
- 当前编辑器快照没有实际文件路径时，`Open` 禁用，或只聚焦当前编辑器文档。

## 与全局 Batch Run 操作的关系

每行的 `Run` 和 `Stop` 是行级操作。

Batch Run 面板仍可以保留全局操作，例如：

- `Start all`
- `Stop all`
- `Clear`

行级按钮与全局按钮必须职责清晰：

- 行级 `Start` / `Stop` 只影响当前行。
- 全局 `Start all` / `Stop all` 影响整个 Batch Run 面板中的所有行。
- 全局 `Clear` 用于清除 Batch Run 面板中所有已经打开的 workflow 路径和对应列表项。
- `Clear` 不是清除日志，也不是只清除已完成运行记录。
- 如果仍有 workflow 行处于运行状态，建议禁用 `Clear`，或先要求用户确认停止相关实例，避免界面把仍在运行的任务直接移除。
- 行级操作产生的运行实例仍然要使用独立的 RunId、独立日志和独立广播作用域。

## 打开文件行为

`Open` 按钮需要根据 workflow 来源处理：

- 文件来源：打开 `.rw` 或兼容的 `.json` workflow 文件到编辑器。
- 当前快照来源：如果当前快照关联了已保存文件，可以打开对应的当前文件；如果没有文件路径，则按钮禁用并显示提示。
- 文件不存在或无法打开时，在该行显示错误，不执行 `Run`。

## 交互结果

实现完成后应满足以下验收条件：

1. 底部状态栏同时存在 `Log` 和 `Batch` 两个入口按钮。
2. 点击 `Batch` 可以展开底部工作区并切换到 Batch Run Tab。
3. Batch Run 双击空白区域能扩展到整个画布区域，再次双击恢复。
4. Batch Run 中每条 workflow 按行排列。
5. 每行最左侧按 `Start`、`Stop`、`Open` 顺序显示三个按钮，且 `Open` 右侧显示 workflow 文件绝对路径。
6. 行级 `Run` 和 `Stop` 只控制当前行，不影响其他 workflow。
7. 每行可以显示 workflow 名称、完整文件路径、实例状态和错误信息。
8. workflow 行高与 Logs 面板日志行一致，含按钮的工具行与 Logs 工具栏比例一致。
9. Batch Run 在明色和暗色主题下均使用主题资源，不出现写死的单主题颜色。
10. 全局 `Clear` 按钮清除所有已经打开的 workflow 路径，而不是清除日志或仅清除完成记录。
11. 行级运行实例与全局 Batch Run 实例都具备独立 RunId 和运行隔离；Log 面板提供 RunId 筛选框，可按完整 RunId 或前缀快速聚焦实例日志。
## 当前实现补充

- 每行实例数量限制为 1–50；输入非法值在 Start 前自动归一化。
- `MaxConcurrency=0` 表示整个 Batch 面板不限制并发；非零值由所有 Batch 行共享。
- Batch 行级 `Start` 与工具栏 `Run` 使用相同的持久运行语义：启动后保持 Running，直到用户点击行级 `Stop`/`Stop All`、节点失败或 `AutoRunStop` 请求结束；Batch 不再把有限工作流在 Run 返回后自动完成。
- Stop/Shutdown 的节点级失败写入运行结果的 `CleanupError`；成功运行如果清理失败会显示为 Failed。
- Batch 运行中禁用该行 `Open`，避免路径显示与实际运行内容不一致。
- 排队中的实例可以被单独 Stop，并立即以 Cancelled 结果退出，不必等待其他实例释放并发名额。

- Log 面板按 RunId 为每个实例保留最近 50 条 `ERROR` 日志，便于运行失败后快速定位；全局日志仍限制为最近 2000 条。
- Batch 行状态和汇总错误统一使用 `EffectiveError`，即运行错误与 Stop/Shutdown 的 `CleanupError` 合并后的有效错误。
- Batch 面板按钮、Tooltip 和文件选择标题已接入 `Loc` 本地化资源；切换中英文时界面即时刷新。
- Batch 启动、停止、运行模式和并发配置会写入日志摘要，方便复现一次批次的实际运行参数。
